The one latency claim we make

Throughput is too noisy to gate on shared runners, so it is not in the table above at all. This single scoped measurement is the exception.

  • 01 Warm has(), in-region p50 5.27 ms · p99 12.71 ms n = 2,000, run 2026-07-27 from AWS CloudShell in us-east-1, against the published npm package rather than a local build. Warm-only seeding with no cold generation, so every call had to reach DynamoDB and the hot cache could not mask it.
  • 02 The honest reading “p99 inside budget” Not “always fast”. A second independent run agreed on every percentile to within about 0.5 ms — that agreement, rather than either run alone, is the reason to believe the distribution. If your budget is sub-millisecond, this number is telling you to use Redis.

Method

Real services

S3 and DynamoDB in us-east-1 at on-demand rates. No LocalStack, no emulator, no simulated latency — a LocalStack rehearsal exists for mechanics and is deliberately not committed as evidence.

Metered at the wire

Operation counts come from the SDK. DynamoDB capacity comes from AWS's own ConsumedCapacity field, not from our model of what a write ought to cost.

Gated, both directions

Every figure on this page is checked against bench/results.json and docs/benchmarks.md by a build gate — and the check also fails on a figure the sources cannot account for, so a number cannot improve without evidence either.

What these numbers do not establish

Each of these is a real limit on what you should conclude, and each is here rather than in a footnote because a caveat nobody reads is not a caveat.

  • 01 Published rates × wire-metered ops — not a cloud bill not reconciled Request tiers and storage-class transitions are unmeasured, and reconciliation against Cost Explorer is blocked on account access. This is arithmetic over real counts, which is stronger than a model and weaker than an invoice.
  • 02 Cost, not latency one scoped run One latency measurement is published above and it is scoped narrowly on purpose. Everything else on this page is a bill, not a stopwatch.
  • 03 Your region and workload move the crossover estimateCost() These are us-east-1 on-demand rates at 8 KiB items with the hot cache off. Feed your own pricing profile in and get your own crossover — the same function generates this page. How.
  • 04 The intersection window is not soak-tested no intersect in soak The long-running soak exercises the write and read paths but issues no intersect calls, so it says nothing about intersection memory over time. The measured run is a single operation, not a duration.
