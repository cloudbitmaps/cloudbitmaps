The GCS driver redacts a credential anywhere in an error's text: a proxy's page or a JSON body that quotes the request (which the SDK makes the error's message on a download, and wherever a body lists no errors) no longer puts the bearer token in the error the driver throws. In that error, the value under a credential's name is redacted (`authorization`, `x-goog-encryption-key`, `x-goog-api-key`, `X-Goog-Signature`, `X-Goog-Credential`, `access_token`, `refresh_token`, `client_secret`, `private_key` and the like; `client_email` and `private_key_id` are kept), as are the value after one in a header list or under one in a map, the value beside one in a record (a `{ name, value }` pair, a `{ th, td }` row; a number, a boolean, and a Google error item's `message`, `reason` and `location` are kept), and, anywhere in the text, a credential header line, a credential after its name (a cookie's every value included), a bearer token after its scheme, a Google access token (`ya29.`), a JWT, a signed URL's signature, a PEM private key's body, the text of an element named for a credential (a `<CanonicalRequest>` a service quotes back) and the text of the cell after one that names a credential, after a heading or a caption too. A credential in any other form is not recognised, and a text these steps cannot finish is replaced whole. A GCS error that carries its transport or shows a credential, and every error it reaches (its `cause` chain, an `AggregateError`'s `errors`), is now thrown as a deep copy of its plain data: a native error with the same prototype, name, message, stack, `code`, `status` and `errors`, with `response` reduced to its status and status text, so classification is unchanged, with no `config`, request, agent or socket, no function or accessor and nothing nested deeper than ten levels; the live error is never changed. A cause chain of any length no longer makes the scrubber throw `RangeError`.
