'@cloudbitmaps/s3': patch
---

An S3 error carries no credential that S3 or a proxy quotes back, and is thrown as a deep native copy. An SDK error that carries its transport or shows a credential, and every error it reaches (its `cause` chain, an `AggregateError`'s `errors`), is now thrown as a copy of its plain data: a native error with the same prototype, name, message, stack, `$metadata`, `$fault`, `Code` and request id, so classification is unchanged, with no `$response`, no unparsed body (`$responseBodyText`), no function or accessor and nothing nested deeper than ten levels; the live error is never changed. In the copy, the value under a credential header or field name is redacted (`x-amz-security-token`, `x-amz-s3session-token`, an SSE-C key, and the signature and canonical request S3 quotes when it refuses a signature, `SignatureProvided`, `CanonicalRequest`, `CanonicalRequestBytes`), as are a credential header line, a SigV4 signature (`Signature=`, `X-Amz-Signature=`, also percent-encoded) and a session token or SSE-C key after its header name anywhere in the text; the access key id is kept. A credential in any other form is not recognised, and a text too large for these patterns is replaced whole.
