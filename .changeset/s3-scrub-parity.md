---
'@cloudbitmaps/s3': patch
---

The S3 driver redacts the signature, canonical request and session token S3 quotes back in an error (`SignatureProvided`, `CanonicalRequest`, `CanonicalRequestBytes`, and `Token-0` on `ExpiredToken` and `InvalidToken`), and the credentials a proxy's page or an unparsed body quotes. In the error the driver throws, the value under a credential header or field name is redacted (`x-amz-security-token`, `x-amz-s3session-token`, an SSE-C key, those S3 fields and the like), as are the value beside a credential's name in a list or a record (a header table's row, a `{ name, value }` pair, `ArgumentName` and `ArgumentValue`), a credential header line, a SigV4 signature (`Signature=`, `X-Amz-Signature=`, also percent-encoded) and a session token or SSE-C key after its header name anywhere in the text; the access key id is kept. A credential in any other form is not recognised, and a text too large for these patterns is replaced whole. An SDK error that carries its transport or shows a credential, and every error it reaches (its `cause` chain, an `AggregateError`'s `errors`), is now thrown as a deep copy of its plain data: a native error with the same prototype, name, message, stack, `$metadata`, `$fault`, `Code` and request id, so classification is unchanged, with no `$response`, no unparsed body (`$responseBodyText`), no function or accessor and nothing nested deeper than ten levels; the live error is never changed.
