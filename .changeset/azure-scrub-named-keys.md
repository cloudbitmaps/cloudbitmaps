The Azure Blob driver redacts what Azure, a proxy's page or a gateway's body quotes of a request: a credential header a user's pipeline adds (a cookie, an API key, a customer-provided key) no longer reaches the error the driver throws through the string to sign a 403 quotes, the `HeaderValue` of an `InvalidHeaderValue`, a JSON or XML body listing the request's headers as records, or a page listing them as a table or inside a line. In that error a credential header line (the string to sign's `x-ms-encryption-key` and `x-ms-source-encryption-key` lines included), an `Authorization` value, a cookie, a customer-provided key or an API key after its name anywhere in a text, the text of the cell after one that names a credential, and the value beside a credential's name in a record (the `...Value` beside a `...Name`, a table row's other cell, the same index of a parallel list) are redacted; a number, a boolean, `code`, `errorCode` and `message` are kept, so classification is unchanged. `x-ms-source-encryption-key`, `encryptionKey`, `accountKey` and `token` are credential names too, and a key that quotes a credential is redacted. An error whose only credential sat in a named property of a list, a map or a set is copied without it, a list, map or set given to the scrubber is copied, a sparse list stays sparse, a copied `DOMException` stays readable, and a copy scrubbed again is returned as it is. A credential in any other form is not recognised.
