# `tests/` — every package, tested from one place

The tests for all six packages live here, at the repository root, rather than inside each package — because many
of them drive the `CloudRoaring` facade and core's internals together, and a test that crosses package boundaries
has no single package to belong to.

Imports use the `@/…` alias (`import { … } from '@/core/crbm-storage-source'`), which `vitest.config.ts` and the
root `tsconfig.json` map onto the packages' sources. So a test reads the source directly, while the published
entry points are exercised separately by `scripts/smoke.cjs` — through the `exports` map a consumer actually
resolves.

## Running them

| command | runs |
|---|---|
| `pnpm test` | everything below **except** `integration/` — no containers, no network. It does need the git history: `docs/calibration-reports.test.ts` checks that each calibration evidence file was committed once and never edited, so a shallow clone fails it |
| `pnpm lint:arch` | `arch/` only |
| `pnpm test:integration` | `integration/` only, against real backends — start them first with `docker compose up -d`, and run `pnpm build` first too |
| `pnpm vitest run tests/docs` | one directory, while working on it |

## Full strength

A few tests are heavy: property suites that draw many cases, a namespace listing of a quarter-million rows, thousands of
native bitmaps measured, each cardinality in a fresh process. On a pull request they run a reduced size, so a push stays
cheap; a scheduled run keeps the coverage by running each at the size it always had.

| | runs | how |
|---|---|---|
| default (a pull request, `pnpm test`) | each heavy test at its reduced size | nothing to set |
| full (the nightly lane) | each heavy test at its full size | `CB_TEST_STRENGTH=full pnpm test` |

Run full strength locally before you change one of these tests or the code under it, and when a nightly run is red.
Unset means reduced; any other value throws, the empty string and a misspelling such as `Full` included, so a
variable that expanded to nothing cannot leave a run at the reduced size.

The switch is read in one place, `helpers/strength.ts`, which holds both sizes of every heavy test, and the test file
that must ask for it, in one table; a test asks `heavy('name')` for its size and never reads the environment. To make
another test reducible, add a row there with the size it has today as `full` and a smaller `reduced` that still trips
the failure the test exists to catch (run the failure case at the reduced size and see it fail), and a row in
`ci/test-strength.test.ts`, which fails until it has one. That test holds each full size to the literal the test carried
before its reduction, checks that each named file asks for its size, that the helper hands out the full sizes when the
variable is `full` and throws on any other value, that the nightly workflow sets the variable on every step that runs
`pnpm test`, that its pull-request paths are exactly the workflow, the switch and every file the table names, and that
no other test file names the variable.

What a reduced size keeps: for each, the failure its test exists to catch still fails at it, for the failures tried. For
the four property run counts that is not a promise about a bug only the deepest or widest shapes show, which a smaller
sample reaches less often; those shapes are pinned as examples that run at every strength.

| test | what it sizes | full | reduced |
|---|---|---|---|
| `bench/calibrate-large.test.ts` | random layouts the range-cap property is tried on (when reduced, a subset that holds every chunk weight and wanted share) | 40 | 10 |
| `core/combine-many.property.test.ts` | cases, one group; cases, many groups under a range | 30; 20 | 8; 6 |
| `core/combine-many.feed.property.test.ts` | cases, fed operands; cases, fed operands under a range | 60; 30 | 15; 8 |
| `core/retention-hard-purge.test.ts` | segments created, retired and purged (`docs/guide/correctness.md` quotes the full size) | 10,000 | 1,000 |
| `core/erase-namespace-bounded.test.ts` | rows in the listing admitted exactly at the ceiling and destroyed one by one (full passes no ceiling, so it is the shared default of 250,000); the refusal one row over the default runs at 250,001 rows on every run | 250,000 | 25,000 |
| `core/combine-ledger.test.ts` | bitmaps measured per cardinality, at 3,000 and 20,000 ids a chunk only (the smaller cardinalities, which have the least headroom and cost the least, always use 8,000) | 8,000 | 4,000 |
| `core/load-sorted-heap.test.ts` | ids in the largest of the sorted load's three heap tiers (the others are a tenth and a hundredth of it), and in the unsorted load it is contrasted with | 10,000,000 | 1,000,000 |
| `roaring/codec-oracle.test.ts` | cases for each oracle property (the several-chunk one runs half); and subsets tried in each small window, 2^12 or 2^16 | 200; 65,536 | 40; 4,096 |
| `roaring/codec-oracle-hostile.test.ts` | mutated, truncated and extended payloads every codec is held to the structural check on | 100,000 | 10,000 |

The nightly lane is [`.github/workflows/full-nightly.yml`](../.github/workflows/full-nightly.yml): `pnpm test` at full
strength on `main`, on each Node version `ci.yml` tests, every night and on demand, and on a pull request that changes
the workflow, the switch or one of these files. It gates nothing; a red run fails the workflow run on the Actions tab.

| `integration/` | The S3, GCS and Azure Blob drivers against MinIO, fake-gcs-server and Azurite from `docker-compose.yml`, and the calibration harness, assembled, in a rehearsal against MinIO with faults injected on purpose. And `ts-roaring.test.ts`, which holds the TypeScript codec to what the oracle cannot see from outside: the cardinality it keeps through every container kind change (checked against a plain `Set` over random add, remove and combine sequences, from an empty bitmap, from ids and from a decoded run container), the ids it refuses to write, the operands it will not mix, hostile bytes refused as native refuses them, truncation at every offset, self-combine and clone independence per container kind, and the bytes it checked being the bytes it reads when a `Uint8Array` or a Node `Buffer` over shared memory changes during the load. And `ts-roaring-fast.test.ts`, which holds the TypeScript codec's fast paths to a plain `Set`: every pair of container kinds (array, bitset, run, a few values against thousands) through every in-place combine with the operand left alone, ids added and removed in bulk across many keys in any order, a decoded bitmap whose small containers share storage and change one at a time, an iterator that is a class and not a generator, and `encodeChunks` serializing lazily from a snapshot: nothing is serialized until a chunk is asked for, a change made meanwhile does not reach the chunks, and a bulk load's periodic yield splits the cut again (counted from inside the load, with the bitmap changed at each yield). And `ts-roaring-fast-paths.test.ts`, differential tests of the same fast paths against the native codec, which check the gallop around its skew of 16 (one either side, the first and last element, an empty side, equal arrays), popcount and word-loop patterns, run edges (a run to 65,535, a split, word boundaries), copy-on-write of shared containers against every mutator before, in the middle of and with a clone during an `encodeChunks`, a bitmap combined with itself, and decoded bitmaps that must not alias their input (a `Uint8Array`, a `Buffer`, a pooled `Buffer`, a `SharedArrayBuffer`, an offset subarray). And the lease on a pin: every read site of a leased handle throws past its lease, as a receiver, an operand, an exclude and an `*Into` target, a stream at its next chunk, a pinned generation surviving 12 and then 100 later loads, through two stores, each interleaving of a lease write with a load, an erasure, a rollback, a shred and a paused collector, simultaneous takers, clock skew in both directions, and a source scan that fails when a method of `Segment` that reaches data does not check a lease. And `codec-switch.test.ts`, which asserts the codec in force is the one the running vitest project asks for (the `ts-codec` project flips the store package's internal codec switch to the TypeScript codec in its setup, `setup-codec-ts.ts`), so that project cannot pass on native by accident. |
| `tools/` | `@cloudbitmaps/tools`: the cost model, every term held to the requests the engine makes by counting what it sends (a load at `keep` 1 to 64, a cold intersect, the pointer refresh, the retention sweep), its prices pinned whole, the Redis it sizes to the data, a grounded report from the size `stat()` reports, and the refusals of an input of the wrong shape. | `setup-codec-ts.ts` | Not a test: the setup of the `ts-codec` project in `vitest.config.ts`, which re-runs the flavor's, core's, the engine's end-to-end and the local-files driver's suites (`TS_CODEC_SUITES`) with the store package's internal codec switch on the TypeScript codec, native staying the default everywhere else. The setup also guards the leg: it wraps the native codec's methods and fails a test in which one ran for a store (the package facade is the nearest caller on the stack, or only library code is), which is how a store that was built before the flip, and so kept the native codec, is caught. A store therefore has to be built inside a test or a hook, never at module scope. The setup restores the native codec in `afterAll`. Run it alone with `vitest run --project ts-codec`. |

## The documentation gates

Everything in `docs/` exists because a document drifted from the code, the release or the site, and something
published it. Each compares prose with the thing it describes, so the drift fails a build instead of reaching a
reader.

| gate | fails when |
|---|---|
| `agents-md.test.ts` | `CLAUDE.md` stops being a symlink to `AGENTS.md`, in git's index or on disk, or `AGENTS.md` stops being the regular file — so a save that replaces the link with a copy cannot split the agent instructions in two. The on-disk check is skipped on a checkout without symlink support. |
| `api-reference-sync.test.ts` | `docs/guide/api-reference.md` and the exported surface disagree — in **either** direction. |
| `audit-kinds-enumerated.test.ts` | `docs/guide/dashboards.md`, `docs/guide/observability.md` or `site/architecture.html`, the three pages that list the audit event kinds, lists fewer than all of them. |
| `calibration-reports.test.ts` | A real-cloud calibration run's report, or the benchmarks page's section on the latest run, leaves out a headline figure its evidence supports, or states a dollar amount, percentage, duration, byte size, bit rate or ratio, or a number written before the request, chunk, id, load or intersect it counts, that the evidence cannot account for at the precision it is written, or beside the words for another claim. Also when the evidence is not a complete, self-consistent real run, or more than one commit has touched it; when a bill's rows disagree with the run's derivation on cost or label; when a report's request ledger disagrees with the evidence on any request or its billing class; and when its table of cost by overlap does not follow from the request shape the run measured. Only the latest report is held to the live model; each earlier report is held to the model recorded for it in the test's `RECORDED_MODELS` (the figures it states as expected: what a `store.load()` bills by kind, the pointer refresh, the Redis line), so an engine change edits no dated report, and a report that stops being the latest fails until its model is recorded. |
| `changelog-released-sections.test.ts` | A released section of `CHANGELOG.md` differs, in any line, from the section its release tag carries: an entry removed, edited or added after the release. `[Unreleased]` changes freely, and a version newer than every tag is the release being cut. A past release that must be corrected is named, with its commit and reason, in the test's `CORRECTIONS`; the section at that commit is the baseline from then on. It needs the history and tags, so a shallow checkout fails with the command that fetches them. |
| `changelog-unreleased-kept.test.ts` | The checked-out head's `[Unreleased]` lacks an entry that `[Unreleased]` had at the merge base with `origin/main`, and no released section of the head has it: a branch that deleted another change's entry, as a bad merge-conflict resolution does. An entry is known by its bold title (its first line when it has none), so rewording its body keeps it and changing its title fails; a release cut that moves entries into a version section passes, but a title an older release already carries does not account for a dropped entry. An entry meant to go is named, with a non-empty reason, in the test's `DROPPED_ON_PURPOSE`; a row excuses only a drop the branch makes, so once its change has merged it excuses nothing and `main` stays green. It needs the history and `origin/main`, so a shallow checkout, or one without that branch, fails with the command that fetches them. On `main` itself the merge base is the head, so it passes. |
| `doc-sample-typecheck.test.ts` | A TypeScript sample in the guides, the README or a package README that carries `<!-- typecheck -->` above its fence compiles against the package sources under `strict`, with `skipLibCheck: false` and no explicit `any`, each as its own module; `<!-- typecheck: store -->` also declares the `store` the docs elide, and `<!-- typecheck-skip: why -->` marks a deliberately partial sample and must say why. A marker with no TypeScript fence after it fails, a prose code span is not a marker, and the compile step is tried on samples that must pass and must fail. A fence with no marker is neither compiled nor said to compile. |
| `docs-claims.test.ts` | Install, cache, `ReadonlyBitmap`, retention-grace and seal-bound claims: the install line for the `roaring` package from npm names the version the flavor pins, a `ReadonlyBitmap` is not offered to a method of that package or to `JSON.stringify`, the retention grace names the window it must outlast, the seal bound is not called unreachable and states the full-width figure, and a data key per generation is a planned item. |
| `code-fence-sanity.test.ts` | A TypeScript sample in the docs makes a mistake that stops it running: it declares a name twice at the top level, declares `storage` or `registry` but uses an undeclared `backend`, declares `backend` but uses an undeclared `registry`, passes `new CloudRoaring({ … })` a key it does not take, at the top level or inside a group, or passes `S3Storage`, `GcsStorage` or `AzureBlobStorage` a key it does not take. |
| `dependency-claims.test.ts` | A count of third-party dependencies does not say whose it is — "zero third-party dependencies" is true of core and false of the family. |
| `describes-the-present.test.ts` | A tracked text file — code, docs, config or a workflow — tells the library's past without naming a version. ## Conventions

- **A gate is verified in both directions.** Plant the defect it exists for and watch it fail; then check that the
  honest look-alikes pass. A gate that has only ever passed is not known to work.
- **Derive, don't list.** A test that hard-codes the set of things it checks goes stale the day a new one is added.
  Read the set off the filesystem, the exports or the source, the way the lockstep and figure gates do.
- **When an honest collision trips a gate, rename the collision rather than widening the gate.** A pattern loosened
  to let one legitimate case through stops catching the illegitimate ones.
