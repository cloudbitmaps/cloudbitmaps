# `api-surface/` — the public type signatures, snapshotted

One file records every public type signature, and one lists the changes and additions to it that were agreed. `scripts/api-surface.cjs`
reads and writes them; [CONTRIBUTING](../CONTRIBUTING.md#commands-the-gate) says when it runs.

| file | what it holds |
|---|---|
| `surface.json` | One entry per exported symbol of every public entry point (each package's `exports` map, subpaths included), and one per public member of a class, interface or enum, with its full signature text and each overload. A type that a public signature names and no entry exports is recorded too, with its members and the types they name, under a `(referenced)` key; a type from outside the workspace is not expanded. A class that declares no constructor is recorded with the one it inherits (see **Constructors** below). Sorted, with no path in it. Regenerate with `pnpm api:surface` after an intended change; `pnpm api:surface:check` fails if the built declarations are not this file. |
| `internal.json` | The same lines, for every entry point a package lists in `cloudbitmaps.internalEntries` in its `package.json` (today, the main entry of `@cloudbitmaps/core`). Such an entry is outside the stability promise: it is not in `surface.json`, and a type only it exported is recorded there as `(referenced)` when a public signature names it. The file is not compared with a base branch; it exists so a change to the internal entry shows in a diff, and a release reviewer reads it. `pnpm api:surface` writes it and `pnpm api:surface:check` fails if it is out of date. |
| `allowed.json` | A JSON array of `{ "entry", "reason" }` rows, empty in the normal state. An entry this branch removes, changes or adds against the base branch's snapshot fails `--against` unless a row names it. `entry` is the exact key, or a prefix ending in `*` that holds a package and at least the start of a symbol's name (a bare `*`, or a prefix that stops before a name, is refused), and a row without a reason fails. A row excuses a change only if the base branch's `allowed.json` does not already have the same row, entry and reason, so a row left over from an earlier change excuses nothing and can be deleted at any time; a later change to the same entry needs a row with a reason of its own. A parameter rename is a change and needs a row. Making an entry internal is also a reviewed change: an entry that is internal on this branch but has keys in the base branch's snapshot fails `--against` unless a new row has the exact entry `<specifier> (internal)` (for example `@cloudbitmaps/core (internal)`). That row takes the entry's own lines out of the promise, never a type that is still promised: a type the entry exported that a public signature still names (now recorded as `(referenced)`), or that another public entry of the package now exports, is compared under that key with the base's lines for it, so a change to it needs a row of its own. The other way, a `(referenced)` type that a public entry of its package starts to export is compared under that entry's key, so exporting it unchanged needs no row: the type was already in the promise. |

**Every addition needs a row.** A new export, a new member of a class, interface, enum or object type, a new type with its members, and a new `(referenced)` key each fail `--against` as `added: <key>` with "a new public entry; add a reason row", until a row this change adds names them. One prefix row (`@cloudbitmaps/roaring Foo*`) covers a new type and all its members. A new `(referenced)` key is a public signature that starts naming a type no entry exports: a caller can reach that type and cannot import it by name, so export it, or say in the row why it stays unexported. An optional member (`name?:`, `name?()`) added to an interface or object type the base already has binds no implementer and still needs a row, because it is a new promise. A required member added to one (a property or method without `?`, or an index, call or construct signature) fails with "a required member added to an existing interface" instead, because it breaks every caller that implements or constructs that type. `surface.json` records which members are required under `required`, decided from the declaration, not from the printed text. An entry listed in `internalEntries` is not in `surface.json`, so an addition there needs no row; `internal.json` shows it in the diff.

**Constructors.** A class that declares no constructor is recorded with the one it inherits, under its own `Class.constructor` key and printed as the nearest base in the workspace declares it, each overload numbered as a declared one is. So a class that declares a constructor of another shape reads as a change, with both texts, and a change to a base's constructor reads as a change in every class that inherits it; a class that declares one identical to what it inherits changes nothing. For example, `class IntegrityError extends CloudRoaringError {}` is recorded with `IntegrityError.constructor` as `constructor(message: string);`, and giving it `constructor(message: string, detail?: number)` fails as `changed:`. A class whose chain declares no constructor records none (the declarations print none; it takes no arguments), and so does one that inherits from outside the workspace (`extends Error`, whose name the header carries) or from a base that is not a class; declaring a constructor on such a class reads as an addition, which needs a row. A private constructor is not recorded.

**What the gate does not see.** A change in behaviour behind an unchanged signature is for tests. Overloads are compared in
declared order, so one appended after the last reads as an addition rather than a change (it still needs a row). A type
from outside the workspace is known by its name in the signatures that use it. Private members are not public and are not
recorded, so removing a `private constructor()` from a class with no base, which makes `new` callable with no arguments,
is not seen. A member added to a class reads as a new entry, not as a required member, even when it is abstract, though
it binds a subclass. An inherited constructor prints as its base declares it, type parameters included: a class extending
a generic base (`extends Base<string>`) that then declares the same constructor with the type filled in reads as a
change. A TypeScript upgrade that changes how declarations print needs one `pnpm api:surface`. A type the snapshot tells
apart by file (a name taken twice in one package, recorded with its path after the name) is not followed between its
exported and `(referenced)` keys: such a move reads as a removal, a change or an addition, and needs a row. A type of
a newly internal entry is followed by its name, so another type of the same name that another entry of the package
newly exports is compared with it, which reads as a change: rename the collision.
