Usage · @cloudbitmaps/roaring 0.1.0

Zero setup, then the same code in production.

The in-memory drivers need nothing — no bucket, no table, no credentials. Swap them for S3 and DynamoDB later and every line above the constructor stays as it was.

1 · INSTALL & VERIFYNPM
$ npm i @cloudbitmaps/roaring
$ npm audit signatures   # OIDC + SLSA provenance
SUPPLY CHAIN

Published tokenlessly from CI via OIDC with SLSA provenance attached, so you can verify the tarball came from the commit it claims. One runtime dependency; cloud SDKs are optional peers you already have.

2 · QUICKSTART.TS — SIX LINES TO A WORKING STORESCROLLS IN ITS OWN BOX
import { CloudRoaring, MemoryWarmDriver, MemoryColdChunkSource } from '@cloudbitmaps/roaring';

const store = new CloudRoaring({
  warm: new MemoryWarmDriver(),
  cold: new MemoryColdChunkSource(),
});

const vips = store.segment('high-value-shoppers');
await vips.addMany([75, 99_999, 1_234_567_890]);  // grouped by chunk, one write per chunk
await vips.has(1_234_567_890);                    // true
await vips.count();                                // exact cardinality, 0 payload reads

Going to production

Only the constructor changes. Nothing above it knows which tier it is talking to.

3 · SWAP THE DRIVERS
const store = new CloudRoaring({
  warm: new DynamoWarmDriver({ table: 'bitmap-deltas' }),
  cold: new S3ColdChunkSource({ bucket: 'my-segments', prefix: 'v1/' }),
  hot:  { maxChunks: 512 },   // optional bounded LRU
});

API

Deliberately the shape of an in-memory Set. What is new is where the bytes live, not what you call.

METHOD DOES TOUCHES
add(id) · addMany(ids)Appends to the chunk's delta row. Ids are grouped by chunk first, so a bulk add is one write per chunk, not per id.warm
has(id)Resolves one chunk: hot if cached, else cold payload merged with warm deltas.hot → warm + cold
remove(id)Records a tombstone in the delta row. Cold objects are never mutated in place.warm
count()Sums per-chunk cardinality from metadata. Exact, not estimated — and it never opens a payload.metadata only
intersect(other)Async-iterates the intersection. Compares chunk keys first and fetches only shared chunks; streams the AND inside a 128 MiB window.shared chunks only
publish()Folds deltas into a new immutable cold generation and drops the rows. Schedule it; don't call it per write.cold
estimateCost(profile)Your region and rates in, projected bill out. The benchmarks page is generated from this same function.nothing — pure
exportSegments()Writes every segment out in the documented .crbm format. The one-command exit.cold

Ten drivers

Warm and cold are independent — pick one of each. Anything with a range read works as cold; anything with cheap small writes works as warm.

S3 GCS Azure Blob R2 DynamoDB Firestore Cosmos DB Postgres Filesystem Memory

Estimate your own bill

Our numbers are us-east-1 on-demand. Yours are not. Feed your own rates in and get your own crossover — the page cannot drift ahead of the library because both call this function.

const bill = estimateCost({
  writesPerSec: 40,
  readsPerSec: 800,
  pricing: myPricingProfile,
});
OPERATIONAL CHECKLIST
  • Schedule publish() — deltas are not free forever.
  • Bound the hot cache to something your runtime can actually hold.
  • Keep one old generation if you want cheap point-in-time snapshots.
BEFORE YOU COMMIT

This is pre-1.0 and single-maintainer. The real risk is operational maturity, not losing your data — the bytes are immutable, the format is documented, and they are in your bucket.
