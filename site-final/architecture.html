Architecture · codec-independent

Only the chunks that can possibly contribute.

Every id splits into a 16-bit chunk key and a 16-bit remainder. The key is metadata, the remainder is payload, and the two live apart — which is the whole trick. Intersecting two 2,000,000-id segments compares keys first and fetches only the 100 shared chunks of 2,000. The other 1,900 are never requested and never billed.

Which chunks, decided before a byte moves

A single cursor walks both sorted key lists. A key present in only one segment cannot contribute to an intersection, so it is dropped without being read — skipping is the default, not an optimisation applied after the fact.

The whole operation, in four steps

Each step names what it does and what it cost. The numbers are from the same measured run as the panel above.

  1. 01 keys(A) ∩ keys(B) 100 / 2,000 Metadata only. Cardinality per chunk is stored beside the key, so this phase never opens a payload.
  2. 02 Plan the fetch 3,800 skipped Every non-aligned key in either segment. Not deferred and not cached — the request is never issued.
  3. 03 Merge warm deltas one range read Adds and removes since the last publish, read as a range rather than scanned.
  4. 04 Stream the AND 403,200 bytes The cold payload footprint is bounded by concurrency × operands × chunk — the window, not the segment size.

There is deliberately no code on this page. What it owes you is the sequence and its costs; the calls that produce it are on usage, once, where they can be copied.

Three tiers, and what each one is for

A segment is not moved between tiers — it exists in all three at once, and a read is resolved from the cheapest tier that can answer it.

TiersScrolls sideways on narrow screens
Tier Role Cost shape
HOT · RAM A bounded LRU of decoded chunks in your own process. Optional and evictable — correctness never depends on it, only latency. your memory
WARM · NoSQL Per-chunk delta rows holding adds and removes since the last publish. A write touches one small row instead of rewriting a chunk, which is why writes are metered at $0.75 per million rather than costing a PUT each. $0.75 / 1M writes
COLD · .crbm Immutable, generation-keyed objects in your bucket. Never mutated in place, so a reader always sees a consistent generation and an old one can be kept as a snapshot. $0.03/mo · 1.2 GiB

Compaction

Deltas accumulate; reads get slower and warm storage gets fuller. Compaction folds them into a new cold generation and drops the rows. It is a background job you schedule — not a stop-the-world event, and not something the read path waits on. Publish cost is $5.88 per million segments, so batch it.

Exact counts, zero payload reads

Cardinality per chunk is stored beside the chunk key, so count() sums metadata and never opens a payload. It is exact, not estimated — no HyperLogLog, no error bars. $0.14 per million counts.

What must stay true

These are the properties the design would be broken without, not intentions. Each has a named test or a typed guard behind it.

InvariantsHeld by tests, not by intent
Property What it means
intersect is commutative a.intersect([b]) and b.intersect([a]) return the same set, and there is a test named for it.
Bounded transfer Only chunks whose keys appear in every operand are fetched. The cold payload footprint is bounded by the window, not by segment size.
Tombstones are first-class There is a real remove(). The effective set is (cold ∪ warm.adds) \ warm.removes — an OR-merge alone cannot express a delete.
Compaction purges conditionally Warm rows are dropped on the version that was archived, so a write landing mid-scan survives instead of being silently lost.
Cold objects are never overwritten segment.<gen>.crbm plus a LATEST pointer. A reader sees one generation or another, never half of a write.
The object ceiling is reachable S3 allows 10,000 multipart parts; at an 8 MiB part that is a 78 GiB ceiling. Exceeding it raises a typed ValidationError — never a raw S3 400, and never silent truncation.
All tier bytes are untrusted Payloads go through the safe deserialiser behind a hard size cap before they reach the native addon. A corrupt or hostile row is an error, not a crash.

1,156 tests run on every commit, and the compaction and OCC paths carry property and concurrency tests specifically.

What this design costs you

Every architecture is a set of trades. These are ours, and the numbers are measured rather than estimated.

01 · A warm round trip is milliseconds, not microseconds

Measured in-region in us-east-1 on 2026-07-27: p50 5.27 ms, p99 12.71 ms over 2,000 samples, against the published package rather than a local build. That is inside budget for most request paths and disqualifying for some.

02 · Sustained high write rates lose to a flat node

Past 26.33 writes/s the metered bill overtakes $346/mo for a Redis-HA node. We publish the crossover rather than waiting to be asked. See it.

03 · Compaction is an operational responsibility

Skip it and reads degrade as deltas pile up. It is a scheduled job you own, like a vacuum — there is no version of this design where nobody has to run it.
